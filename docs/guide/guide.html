Step 3

Battery, charger & switch

FromTo
Battery red (+)TP4056 B+
Battery black (-)TP4056 B-
TP4056 OUT+One side of the power switch
Other side of the switchESP32-C3 5V pin
TP4056 OUT-ESP32-C3 GND

Charge through the TP4056 USB-C port. The switch cuts power to the whole card.

Read before you power it on
  • A charged Li-Po is about 4.2 V. Never connect it to the 3V3 pin. Use the 5V pin, which feeds the onboard 3.3 V regulator.
  • Check polarity twice. A reversed battery or charger output can destroy parts.
  • Battery goes on B+ / B-. The load (switch + ESP32) goes on OUT+ / OUT-.
  • Use a protected battery or a TP4056 module with protection.
  • Do not short a Li-Po or leave it charging unattended.

Step 4

Software setup

1
Install the Arduino IDE from arduino.cc/en/software.
2
Add ESP32 support. In File > Preferences, add this to Additional boards manager URLs, then install esp32 by Espressif Systems in the Boards Manager. 
https://espressif.github.io/arduino-esp32/package_esp32_index.json
3
Install libraries (Library Manager):
Adafruit GFXAdafruit ST7735 and ST7789Adafruit SSD1306JPEGDEC
4
Get the code: 
git clone https://github.com/AmshenShanu07/Digital-Id-Card-Firmware.git
5
Open firmware/DigitalIdCard/DigitalIdCard.ino.
6
Select the board Tools > Board > esp32 > ESP32C3 Dev Module, then set:
OptionValue
USB CDC On BootEnabled (for Serial Monitor)
Partition SchemeHuge APP (3MB No OTA / 1MB SPIFFS)
Flash Size4MB
7
Upload. Pick the port and click Upload. If the board is not detected, hold BOOT while plugging in USB.

The sketch ships with sample content (12-frame animation + 2 gradient images), so it runs straight away.

Step 5

Use your own GIF & photos

The ESP32 can't read PNG or GIF files, so two Python scripts in tools/ turn them into C headers compiled into the firmware.

terminal
# 1. install once (Python 3.8+)
pip install -r tools/requirements.txt

# 2. animation screen (GIF)
python tools/gif_to_header.py my_animation.gif firmware/DigitalIdCard/animation.h

# 3. still images
python tools/image_to_header.py photo1.png firmware/DigitalIdCard/image_one.h --name imageOne
python tools/image_to_header.py photo2.png firmware/DigitalIdCard/image_two.h --name imageTwo
GIF optionDefaultWhat it does
--quality75JPEG quality 1-95. Lower = smaller file.
--slowdown1.0Time multiplier. 2.0 plays twice as slow.

Every image/frame is scaled and center-cropped to 240 x 280. After converting, upload the sketch again.

Sketch too big? The whole animation must fit in about 3 MB of flash. Use fewer frames, a smaller GIF, or a lower --quality.

Add a third image

1
Convert it with --name imageThree to image_three.h.
2
In the sketch add #include "image_three.h" and append imageThreeData to images[].
3
Add one matching line to scrollingTexts[] and mainTexts[].

Step 6

Customise & fix it

DigitalIdCard.ino - USER SETTINGS
const char *const scrollingTexts[] = {
  "@your.handle \x07 Your Role \x07 Maker",
  "@your.handle \x07 Your Name \x07 Maker",
  "@your.handle \x07 Your Role \x07 Your Name"
};
const char *const mainTexts[] = { "Name", "Role", "Maker" };
#define SCROLL_INTERVAL 25   // ms per pixel, lower = faster

\x07 prints a bullet in the OLED font. Keep mainTexts to about 7 characters. NEXT / PREVIOUS cycle animation → image 1 → image 2.

Troubleshooting

ProblemFix
TFT stays blackRe-check the 5 SPI wires and VCC/GND. Tie BL to 3V3 if present.
Wrong colors / shifted pictureMust be a 240 x 280 ST7789 (tft.init(240, 280)).
"OLED not found!"Check GPIO 0/1. Some modules use 0x3D: change OLED_ADDRESS.
No Serial Monitor outputUSB CDC On Boot = Enabled, baud 115200.
"Sketch too big"Huge APP partition, then shrink the GIF.
Animation too fast / slowUse --slowdown.
Button dead or double-stepsMust connect GPIO to GND. Tune DEBOUNCE_MS.
No power from batteryCheck B+/B- polarity, the switch, and OUT+ → switch → 5V.
Upload failsHold BOOT while plugging in, try another (data) cable.
